# Training benchmark configurations

Download the [benchmark source archive](../assets/benchmarks/openmolspec-benchmark-source.zip), unpack it and work from the extracted directory. The archive includes the launcher, model adapters, data-preparation modules and all 53 configurations. [SHA-256 manifest](../assets/benchmarks/benchmark-source-manifest.json).

```bash
unzip openmolspec-benchmark-source.zip
cd openmolspec-benchmarks
python -m benchmarks --help
python -m benchmarks run \
  --config benchmarks/configs/structure2property/equiformer_v3.yaml --dry-run
```

Download a YAML file to inspect the exact targets, architecture and training budget. Configurations are grouped by task family. The production training workflow reads them with `python -m benchmarks run --config <file>`.

## Spectral language models

Install the optional language-model dependencies in a separate environment. The packaged command accepts a local merged Qwen2 SpecMol or Qwen3 SpectraLLM checkpoint and UTF-8 JSONL with one supervised example per line. Each row has a user prompt, an assistant response, and an optional system message.

```json
{"system":"Answer with the requested count.","prompt":"How many distinct 13C shifts are listed at 18.2 and 58.1 ppm?","response":"2"}
```

```bash
python -m pip install '.[spectral-language]'
openmolspec-train-language --checkpoint /path/to/merged-model \
  --jsonl train.jsonl --output ./new-adapter --max-steps 1 --device cuda
```

The command applies LoRA to the query and value projections and computes loss on the assistant response and end token. Load the saved directory with `PeftModel.from_pretrained(base_model, adapter_directory)`. The package validates this training path by updating and reloading tiny Qwen2 and Qwen3 models with the released tokenizers. The one-step check measures software behavior. The separate evaluation CLI uses merged inference weights.

```bash
openmolspec-bench run --tasks spectroscopy.qa --language-checkpoint /path/to/SpecMol/exported_model \
  --workspace /path/to/OpenMolSpec --device cuda --limit 32 --output qa.json
```

## Fit a task model

These commands run from the source checkout. The assigned-site trainer reads an annotated JSONL gzip and its adjacent checksum manifest. For solvent transfer, use a paired reference library and its matching baseline report. For the gap models, supply the computed spectrum LMDB and the earlier evaluation with sample IDs to reserve. Each command writes weights and an evaluation report.

```bash
mkdir -p runs/example-training
python scripts/train_assigned_hc.py --data /path/to/assigned.jsonl.gz --nucleus 13C --output runs/example-training/13C-assigned --report runs/example-training/carbon.json
python -m openmolspec_bench.solvent_fit --library /path/to/solvent_reference_library.json --baseline results/solvent_transfer_all_reviewed.json --weights runs/example-training/solvent.json --report runs/example-training/solvent-eval.json
python scripts/train_gap_vibrational.py --lmdb /path/to/openspec_test.lmdb --original results/gap_protocol_random128_20261116.json --weights runs/example-training/gap.npz --report runs/example-training/gap-eval.json
```

## SpecMol spectroscopy QA

The released SpecMol-7B model answered 32 four-choice questions counting entries in NMRSpec ¹H or ¹³C peak lists on GPU. Scoring the full decoded answer gave **4/32 correct (12.5%)** and **29/32 valid choices (90.6%)**.

The separate four-GPU LoRA submission uses 8,192 training and 512 validation questions split by connectivity. The 24 November snapshot contains the base-model result above. The adapted-model held-out result is pending.

[Download all questions and decoded choices](../assets/benchmarks/specmol-qa-responses.json)

A separate two-GPU IR + Raman adaptation submission uses connectivity-disjoint splits of 11,632 training, 1,558 validation and 24 test structures. The 24 November snapshot contains its split manifest and submission receipt. Its fitted checkpoint scores are pending.
